# 公司项目介绍文案

## 官网简介

Spiro 是一个围绕日常音频构建的 AI 个人记忆项目。通过音频算法、说话人识别、事件理解和 Agent 内容服务，项目将分散的声音资料整理为可阅读、可回看、可追踪来源的生活内容，并以多层记忆研究和实时语音 Demo 探索持续理解用户的交互方式。

## 完整项目介绍

每天的对话包含大量值得保留的信息：一次计划、一个决定、一段重要交流，以及用户反复关心的事情。Spiro 围绕这些日常资料，建设从音频输入到内容表达的技术链路，让声音逐步形成有时间、有参与者、有上下文的事件。

在算法端，平台组合音频处理、语音活动检测、ASR、说话人切分和声纹匹配，形成可供理解的音段。语义分析继续完成片段判断、转录校对、来源识别与事件聚合，使零散发言成为更完整的生活记录。

在内容端，Agent 平台通过统一任务框架承载事件卡、洞察信件、画像及相关任务。上下文准备、任务版本、模型运行时、结构校验和业务规则分层组织，让内容能力能够持续迭代，并保留结果与来源之间的联系。

在平台端，项目建设 API、异步任务、监控界面、实时事件、异常重试和调试产物管理；配套听审标注、批量实验、版本比较和系统地图，支持算法、产品、工程共同定位和验证问题。

在研究与体验端，独立记忆系统探索如何将对话转化为事实、事件和更长期的观察，并通过多路召回与分阶段生成使用这些信息。实时语音 Demo 则将记忆查询、问题路由、语音回答和认知面板连接起来，展示持续对话的产品方向。

项目坚持从来源到表达的质量检查：不仅观察模型输出是否合理，也检查内容是否属于用户、是否有足够证据，以及一次算法变化是否真正改善最终体验。由此形成覆盖感知、理解、生成、记忆、交互与研发工具的完整工程版图。

## 对外演示的讲解顺序

1. **先展示产品价值**：声音如何成为可回看的生活事件。
2. **再解释算法链路**：从音频、说话人到片段与事件。
3. **展示内容服务**：同一事件底座如何支撑不同任务。
4. **展示平台能力**：任务运行、监控、定位与人工复核。
5. **介绍记忆探索**：信息怎样更新、检索并参与内容生成。
6. **演示交互方向**：实时语音如何连接资料与回答，明确 Demo 状态。
7. **以工程成果收束**：说明已建模块、离线验证及下一阶段边界。

## 展示时的三条表达原则

采用公司与项目视角，介绍各模块如何共同工作；算法指标放在适用样本和任务范围内；对主服务、实验实现、Demo 和历史设计使用一致的状态说明。
