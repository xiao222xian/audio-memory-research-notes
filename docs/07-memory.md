# 多层记忆、更新机制与检索研究

## 从保存事件走向持续理解

项目独立研究如何将持续输入的事件整理为可更新、可追溯的记忆。其核心是保留不同抽象层之间的关系：原始对话支持事实，事实与事件支持更长期的观察，上层归纳不替代下层证据。

本章描述归档中的记忆实验实现，未将其表述为已经合入主 Agent 服务的生产能力。

## L0–L5 的信息分工

| 层级 | 内容 | 主要职责 |
|---|---|---|
| L0 BasicInfo | 产品确认的基本信息 | 为理解提供身份锚点 |
| L1 MemCell | 原始对话单元 | 保留原始依据与溯源材料 |
| L2 AtomicFact | 可独立引用的具体事实 | 支持事实查询与后续更新 |
| L3 Episode | 事件叙事 | 组织某次经历及相关上下文 |
| L4 Foresight | 面向未来的推导信息 | 提供带依据、需考虑时效的前瞻线索 |
| L5 Profile | 相对稳定的观察 | 为内容理解提供长期上下文 |

这些层不是一条逐级压缩后丢弃原文的链。不同类型保留自己的证据和更新方式，避免一个未经充分支持的概括覆盖所有历史事实。

## 记忆如何更新

事实、画像和前瞻信息采用抽取、决策、执行的分阶段流程。抽取产生候选；决策将新候选与已有信息对照；执行负责写入更新。通过显式保留判断与状态，减少新材料简单覆盖旧记录的问题。

编排按依赖关系并行：共享同一只读输入的抽取可以同时进行；依赖前一步结果的更新按顺序处理。事件写入与供检索使用的快照有明确边界，避免内容生成读取半完成状态。

## 多路召回怎样组织

检索结合语义匹配、关键词匹配及不同记忆类型的召回方式。全文和用户发言可以形成不同查询视角，帮助区分整场讨论与用户自己的表达。多个通道经过评分与配额组织，形成供特定任务消费的材料。

语义匹配适合近义表达，关键词有利于明确名称和细节，画像提供稳定背景，事实与事件提供可引用内容。组合策略由消费任务决定，不要求所有问题使用相同上下文。

## 四阶段实验事件卡

```mermaid
flowchart LR
    A[感知本次事件] --> B[结合记忆理解]
    B --> C[决定生成或跳过]
    C --> D[组织最终表达]
```

感知阶段提取观察；理解阶段关联相关记忆；决策阶段选择是否值得生成及表达主轴；写作阶段基于选定材料完成内容。每个阶段保留中间产物和模型轨迹，便于判断错误发生在观察、关联、选择还是表达。

归档实现的记忆下游收敛于事件卡。主 Agent 服务中的信件和画像任务有自己的实现，不能因此推断它们已经接入这套记忆流程。
