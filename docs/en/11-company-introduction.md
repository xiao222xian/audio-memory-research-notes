# Company Project Introduction

English · [中文](../11-company-introduction.md)

## Website introduction

Spiro is an AI personal-memory project built around everyday audio. Audio algorithms, speaker identity, event understanding, and Agent content services organize scattered recordings into readable experiences with traceable sources. Layered-memory research and a realtime voice Demo explore how these experiences can support continuing interaction.

## Full project introduction

Everyday conversations contain information worth keeping: a plan, a decision, a meaningful exchange, or a recurring concern. Spiro builds a technical chain from audio to expression so these sounds can become events with time, participants, and context.

At the algorithm layer, audio processing, voice activity detection, ASR, diarization, and voiceprint matching prepare material for understanding. Semantic analysis adds fragment judgments, transcript correction, source identification, and event aggregation to form coherent records.

At the content layer, a shared Agent framework supports event cards, insight letters, profiles, and related tasks. Context preparation, task versions, model runtimes, schema validation, and business rules are organized separately, enabling iteration while retaining source relationships.

At the platform layer, APIs, asynchronous tasks, monitoring interfaces, realtime events, retries, and debug-artifact management support execution. Listening and annotation tools, batch experiments, version comparison, and a system map allow product, algorithm, and engineering teams to diagnose and validate changes together.

At the research and experience layer, an independent memory system explores facts, events, and longer-term observations through updates, multiple retrieval channels, and staged generation. A realtime voice Demo combines query routing, memory retrieval, spoken responses, and a cognition panel to demonstrate the interaction direction.

Quality checks connect source and expression. The project examines whether content belongs to the user, whether evidence supports it, and whether algorithm changes improve the final experience. The resulting engineering scope spans perception, understanding, generation, memory, interaction, and development tools.

## Suggested presentation sequence

1. Show the product value: audio becoming events people can revisit.
2. Explain audio, speakers, fragments, and event organization.
3. Introduce the content tasks built on the event foundation.
4. Show task execution, monitoring, diagnosis, and human review.
5. Explain memory updates, retrieval, and experimental generation.
6. Demonstrate voice interaction while identifying its Demo status.
7. Close with delivered modules, offline evidence, and capability boundaries.

## Presentation principles

Use the company and project as the subject. Explain how components work together. Keep metrics attached to their samples and tasks. Distinguish main services, experiments, Demos, and historical designs consistently.
