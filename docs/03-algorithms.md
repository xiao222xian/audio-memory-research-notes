# 音频与语义算法体系

## 六条核心流水线

| 流水线 | 技术职责 | 产物与用途 |
|---|---|---|
| 音频转音段 | 解码、重采样、音频处理、语音检测、切分与转录 | 带时间边界的音段及识别文本 |
| 片段分析 | 有意义判断、语义标注、转录校对、来源识别 | 结构化片段事件 |
| 基础事件分析 | 聚合片段、合并信息、综合标题与摘要 | 完整生活事件 |
| 声纹特征提取 | 提取和归一化说话人表示 | 注册及识别使用的向量 |
| 说话人解析 | 历史版本中的跨片段身份统一 | 全局说话人映射 |
| 声纹准入评估 | 有效语音、特征与质量联合评估 | 注册流程使用的评估结果 |

不同流水线按版本和业务需要调用；并非每次请求都完整执行六条。

## 音频感知：把原始信号变为可分析片段

原始声音可能包含静音、混响、背景噪音和多人发言。工程提供人声分离、增强、去混响、重采样和语音活动检测等能力，结合说话人切分为后续模型组织输入。处理步骤由配置和版本决定，避免把任意增强都视为必然有益。

归档中有 Whisper、FunASR 转录路径，以及基于 vLLM 的转录执行方式。说话人切分、语音覆盖与时间对齐共同决定哪些声音进入转录。对短段、重复文字或不合理输出的处理，需要兼顾幻觉控制与真实短语的保留。

工程区分两类结果：模型加载或执行失败需要错误处理或回退；门控后没有有效语音可以是合法空结果。将后者误当成故障重新放宽条件，可能重新引入无证据转录。

## 片段理解：声音、文本与身份共同进入分析

片段层承担语义判断，而不仅是文本摘要。输入包含音频、初始文本、音段时间线、身份线索和上下文；输出组织有意义性、场景、主题、连续性和内容来源。

V3 路径将有意义判断与语义标注合并处理，再在已有 ASR 文本上进行校对和说话人相关标注。标注结果需要映射回原音段，并检查时间关系。失败分支按阶段处理：语义调用错误与“无意义”不同，校对失败时可保留原始转录。

这种编排减少了重复理解同一材料的需求，也让每个阶段的输入输出更容易比较。具体收益需要按固定条件实验，不以调用数量直接推断线上成本或准确率。

## 事件组织：从零散片段形成连贯经历

事件聚合首先通过规则组织转录、类型、场景、来源和说话人信息，再使用模型综合标题、摘要和主题。基础事件保留组成片段的关联，供业务查询及后续内容生成使用。

算法关注两个不同问题：哪些片段属于同一件事，以及最终摘要应该表达什么。短时媒体或错误转录可能影响主题，因此事件层仍需要来源和身份信息，不能只依赖经过压缩的一句话摘要。

## 模型与执行版本的演进

| 维度 | 历史路径 | 后续路径的变化 |
|---|---|---|
| 转录组织 | 在多模态富化中组织转录 | 初始 ASR 文本与校对步骤分开 |
| 语义判断 | 多个独立判断步骤 | 合并部分有意义性、语义与连续性判断 |
| 声纹表示 | WeSpeaker 路径 | ReDimNet2 路径 |
| 身份位置 | 部分身份统一在事件合并阶段 | V3 将匹配放在片段阶段 |
| 推理执行 | 逐段执行路径 | 增加批处理及 vLLM 路径与回退 |

上述为项目内版本演进，不构成对相关开源模型的通用性能排名。

## 算法研发如何验证

研发保留原始基线、标签版本和样本对应关系，通过消融、版本差异和下游回放识别真正有效的变化。评测不仅统计分类指标，也检查错误转录、身份错归、正常内容损失和最终卡片质量。
