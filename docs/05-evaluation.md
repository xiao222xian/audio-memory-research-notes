# 评测与复核工具：让实验可比较，让问题看得见

## 为什么我要建设工具

连续音频质量排查往往需要反复切换录音、转录、预测、卡片和人工反馈。仅靠表格中的一个标签，很难理解模型为什么错，也很难保证多人讨论的是同一条证据。

我围绕实际排查流程建设运行、分析和复核工具，让一次实验从执行到判断形成连续链路。

```mermaid
flowchart LR
    A[固定样本与标签版本] --> B[批量运行与缓存复用]
    B --> C[预测对齐与指标计算]
    C --> D[错误筛选与人工听审]
    D --> E[标签导出与版本比较]
    E --> F[下游回放与交接结论]
```

## 1. 样本对齐与版本比较

### 我处理的问题

不同运行结果不一定天然对齐：同一段相对时间可能出现在不同事件中；历史标签可能经过复审；算法输出数量也可能与人工反馈数量不同。

### 我的处理方式

- 使用事件与时间联合关联样本。
- 显式记录缺失、重复和排除项，不将无法匹配的记录静默丢弃。
- 保留原始基线和历史标签，区分“模型变化”与“真值变化”。
- 在统一集合上计算混淆矩阵，并分析版本间由错变对、由对变错的样本。

公开示意：一次比较至少需要回答以下问题——

| 检查项 | 用途 |
|---|---|
| 输入是否相同 | 防止样本差异被当作模型收益 |
| 标签是否同版 | 防止复审改变分数含义 |
| 是否全部匹配 | 防止缺失样本造成选择性统计 |
| 哪些旧错误修复 | 说明改动收益来自哪里 |
| 哪些新错误出现 | 暴露正常内容损失或新的漏检 |

## 2. 批量运行、失败重试与缓存复用

我编写和使用批量实验脚本，支持并发执行、失败重试和结果汇总。对于只改变一个理解步骤的试验，复用已有阶段结果，仅重跑目标步骤，避免每次从整条音频链路开始。

缓存复用还有实验价值：固定不相关输入，可以减少上游随机变化干扰，帮助判断目标改动的影响。它不意味着所有端到端实验都能直接复用旧生成结果；需要观察下游变化时，仍应重新运行相应阶段。

实验记录中保留版本、模型设置、采样参数、并发与运行标识。记录这些条件是为了判断不同结果是否可比，而不只是为了重新执行一次命令。

## 3. HTML 人工听审页

历史工具将音频、转录、模型输出和人工标签组织在同一页面，并支持以下交互：

| 功能 | 解决的实际问题 |
|---|---|
| 音频按需加载 | 避免大量样本打开页面时同时加载 |
| 单播放器控制 | 避免多条音频同时播放干扰判断 |
| 自动保存进度 | 减少长时间复核中断后的重复工作 |
| JSON 导入与导出 | 让人工结果可以进入后续统计与比较 |
| FP/FN 分类查看 | 让复核围绕明确错误类型进行 |
| 音频、文本、预测对照 | 便于区分转录问题、来源判断问题和标签分歧 |

这里描述的是已归档的工具能力；公开仓库不附真实听审页面、用户素材或伪造的运行截图。

## 4. 辅助诊断与独立盲审分开

诊断时展示模型预测，有助于快速定位差异；建立独立标签时，展示预测可能影响人的判断。两种页面和流程服务不同目的。

我在分析中明确区分模型辅助复审与用户盲审，并在最终报告中记录标签来源。这样能够避免把便于排查的工具产物，错误解释成完全独立的评测真值。

## 5. 端到端追踪页面

片段指标之外，我整理了可追踪事件候选、生成/跳过和引用关系的页面与数据，支持从问题卡片向上游查看。工具服务于具体诊断：是媒体片段残留、事件主题改变，还是生成器在相同材料上做出不同选择？

## 工程价值

这些工具将原本分散的人工操作组织成稳定的工作方式：同样本比较、按错误类型复核、可导出的标签、可定位的生成来源和可接手的实验记录。项目未对人工工时或成本节约进行独立量化，因此这里以实际能力和交付物说明价值。
