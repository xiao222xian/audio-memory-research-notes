# 实时语音 Demo 与前端交互体验

[English](en/08-live-experience.md) · 中文

## 一个可以对话的记忆展示入口

LiveMemory 将记忆召回、语言推理和语音交互连接成前后端 Demo。用户通过麦克风提出问题，后端依据问题类型检索材料，组织回答并播报；界面同时提供认知面板，展示与回答相关的组织结果。

它是单用户演示与研发工具，使用独立导入的记忆语料；不代表已经完成多租户商业服务或全面设备验收。

## 前后端分工

| 层次 | 技术与职责 |
|---|---|
| 前端 | React、TypeScript、Vite；路由、语音操作、回答与认知展示 |
| 后端 | Python、FastAPI；会话管理、语音连接、检索与推理编排 |
| 双向连接 | WebSocket 传递实时语音和会话状态 |
| 记忆输入 | 导入可移植语料，提供运行列表与资料预览 |
| 演示入口 | 产品介绍页面和按配置启用的 Live Demo |
| 运维工具 | 统一 CLI 管理启动、停止、状态与环境诊断 |

## 两类语音链路

**拼装链路**将流式 ASR、中间语言模型与 TTS 组合起来，使转录、推理和播报可以分别观察与配置。**原生音频链路**探索模型直接处理实时音频的交互方式。两类路径由配置选择，不在同一次会话中模糊混用。

界面与后端组织监听、思考、播报等状态，并提供插话相关处理。实际网络、设备和模型服务会影响体验，因此材料介绍实现内容，不使用未验证的固定响应延迟承诺。

## 按问题类型组织召回

| 问题类型 | 处理重点 |
|---|---|
| 事实 | 定位明确资料与相关原始内容 |
| 模式 | 结合多条证据观察重复现象 |
| 洞察 | 在适用条件下进行多视角关联 |
| 计数 | 对具体短语或匹配范围进行计数 |
| 时间 | 按日期和时间范围过滤材料 |

问题路由避免把每次提问都处理为跨领域联想。用户问一个明确事实时，应先得到事实；需要关联理解时，再启用相应推理路径。

## 回答与认知面板同源

语音回答与右侧面板消费同一份组织后的信息包，减少两边独立生成造成的不一致。面板可呈现相关节点、关系和综合信息；调试模式进一步展示召回与工具使用过程。

## 全链路会话记录

研发记录转录、状态变化、召回、工具调用、打断和轮次边界，并为模型调用保存可导航的输入输出轨迹。语音链路故障可以沿状态时间线排查，内容问题可以沿召回和模型上下文排查。

这些工具使 Demo 同时承担产品体验展示与系统诊断作用。公开仓库仅提供脱敏说明，不附真实用户记忆或会话。

ASR 片段组装、HOLD 窗口、barge-in、revision 合并与取消顺序见[实时语音实现细节](16-voice-implementation.md)。
