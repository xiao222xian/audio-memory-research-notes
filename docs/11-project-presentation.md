# 项目介绍与技术问答

## 30 秒介绍

我参与过一个将连续音频整理成个人记忆的 AI 项目，工作重点是可信性治理：避免把外放媒体、别人的话或缺少证据的内容写成用户经历。我把这些问题拆成内容来源、身份归因、证据完整性和最终生成质量，做了多轮控制变量实验，并建设人工复核与端到端追踪工具。在固定复核集上，最终候选的媒体识别 F1 从 75.5% 提升到 84.1%。

## 两分钟介绍

这个项目的基础链路是从录音到转录、内容理解、事件聚合，再由 Agent 生成个人记录。难点是：录到了的内容，并不一定属于用户的经历。

我的工作从用户反馈出发。首先，我梳理整条链路，区分媒体污染、身份错归和无证据生成，确定每个问题应该在哪一层观察。其次，我统一样本关联和标签口径，设计多轮控制变量与消融实验，比较转录依赖、判定规则、外部检测信号及集成方式。

在媒体识别上，同一 116 条复核集的 F1 从 75.5% 提升到 84.1%。我还将候选放进 17 个固定窗口、每窗口 5 轮的下游回放，检查实际卡片。最终候选相比前一集成版本少了两张媒体污染卡片，但与原始基线仍然持平。通过追踪引用和输入，我把残余问题定位到一个反复影响生成的上游窗口。

在无证据生成方面，我分析了 25 条问题样本，区分元信息、音频缺失与低质证据；加入对照后发现，一个看似有效的音质阈值会误拦截大量正常候选，因此没有让它单独承担准入判断。

围绕这些工作，我编写和整理了批量实验、结果分析、HTML 听审、标签导入导出、端到端血缘与系统地图。这个项目体现的是我将产品问题转成实验问题，再用工程工具定位和验证的能力。

## 对技术细节的追问

### 为什么不直接让一个大模型判断要不要生成？

因为输入存在性、内容来源、身份和产品价值不是同一个判断。把它们混在单次输出中，既难以定位错误，也难以知道一次改动改善了什么。我采用分层观察与实验，再检查最终生成效果。

### 为什么要纠正样本映射？

来自不同事件的片段可能有相同的局部起止时间。只按时间去重会误合并，进而改变指标分母。事件与时间联合关联，让不同版本能够在同一集合上比较。

### 缓存复用有什么意义？

它既减少重复运行，也能固定未修改阶段的结果，让目标变量的影响更清楚。需要检查下游效应时，再重跑相应阶段，不能用缓存替代必要的端到端验证。

### 为什么不采用一个音质或重放分数作为门槛？

这些分数与目标有关，但并不直接表示“是否属于用户经历”。必须同时看问题拦截和正常内容损失，单独的高拦截率可能掩盖很大的产品代价。

### 你的工程产出有哪些？

批量运行与重试、阶段性重跑、样本对齐、指标和错误变化分析、HTML 听审、自动保存与 JSON 导出、卡片血缘追踪，以及系统地图和方案交接材料。它们围绕同一条工作链：运行、观察、判断、验证、交接。

### 你的个人贡献与团队系统怎样区分？

我展示的是质量问题拆解、实验策略、评测与复核工具、跨层诊断及交接整理。基础模型、完整服务和其他系统实现是团队背景，不将整个产品归为个人独立成果。

### 如果再推进一轮，优先做什么？

优先补充独立新样本，针对混合场景验证时间切分和事件主题影响，并为生成前准入补齐单事件真值。下一轮应该回答更具体的剩余问题，而不是重复提高同一固定集的分数。
