# 音频算法实现细节

[English](en/13-audio-implementation.md) · 中文

## 一次录音如何成为带身份的音段

音频引擎将处理流程拆成可配置阶段，而不是固定地对每个文件执行所有增强：

```text
解码与统一采样率
  → 可选人声分离 / 增强 / 去混响
  → 语音活动检测与说话人切分
  → 时间段过滤和对齐
  → ASR 转录
  → 每段声纹嵌入
  → 时间线合并与结构化输出
```

入口接收音频字节和版本配置，流水线只返回计算结果；下载、上传、事件存储和下游消息由业务编排层负责。这使同一算法步骤可以在测试、批量实验和服务任务中复用。

## ASR 与切分之间的关系

工程保留 Whisper、FunASR 和基于 vLLM 的执行路径。转录不是简单对整段音频调用一次模型：说话人切分提供候选时间段，VAD 覆盖用于排除缺少有效人声的区域，最短时长和字符速度等检查用于控制短段噪声与异常重复。

其中一种门控路径只转录同时满足说话人区间和语音覆盖条件的片段。返回空列表可以表示没有合法语音，而 `None` 或异常表示执行失败。两类结果具有不同语义：前者不应自动放宽门控重跑，后者可以进入回退路径。

vLLM 路径出现加载失败、显存错误或批量结果不一致时，可回退到逐段推理。流水线在重模型阶段之间执行显存清理和模型缓存管理，使 ASR、说话人模型与人声分离模型能够共享有限 GPU 资源。

## Fragment V3 的双调用语义流程

V3 将片段理解组织为两个职责清晰的模型步骤：

1. **语义标注步骤**：结合音频、已有转录和上下文，判断片段是否有意义，并产生场景、事件类型、内容来源和连续性等信息。
2. **转录校对步骤**：以 ASR 为基础修正同音字或漏字，并补充性别、语气和说话人描述，再映射回原始分段索引。

第一步调用或解析失败会作为可重试的流水线错误处理；第一步明确判断无意义则是合法业务结果。第二步失败时保留原始 ASR，避免校对服务失败导致整个片段丢失。

## 说话人表示与匹配

历史版本使用 512 维 WeSpeaker 表示，后续版本采用 192 维 ReDimNet2 表示。每个有效音段生成嵌入并进行 L2 归一化。注册样本的多段表示采用聚合后再次归一化，用于后续余弦相似度匹配。

V2 的跨文件解析先计算 `(文件, 局部说话人)` 的时长加权质心，再执行带约束的完全链接层次聚类：

- 同一文件中的不同说话人使用 cannot-link，避免错误合并；
- 已确认同一声纹的分组使用 must-link；
- 已确认不同身份的分组使用 cannot-link；
- 聚类内已有身份可以向同组其他片段传播。

V3 将声纹匹配提前到 Fragment 阶段，因此 Basic Event 合并不再重复运行 V2 的跨片段解析。这是版本差异，不是两套算法同时串联。

## 注册准入的三路并行信号

声纹注册评估对有效语音时长、嵌入是否可用和非侵入式质量评分分别计算。质量侧组合 DNSMOS、NISQA 和 DISTILL-MOS；有效语音段拼接后加入短静音间隔，并限制评分长度，避免长音频触发模型边界问题。

三个子评估相互独立：其中一个失败时，其他结果仍可返回。业务层根据结果形成通过或失败原因，下载失败、解码失败、推理错误和超时分别记录。注册评估产生依据，正式注册由业务流程执行。

## 结构化输出的关键字段

下面使用合成数据展示核心数据形态：

```json
{
  "segment": {
    "start_ms": 1240,
    "end_ms": 4680,
    "text": "synthetic example",
    "local_speaker": "speaker_1",
    "identity": {"status": "candidate", "confidence": 0.78}
  },
  "fragment": {
    "meaningful": true,
    "scene": "conversation",
    "content_origin": "mixed",
    "topics": ["planning"],
    "source_segment_ids": ["synthetic-segment-1"]
  }
}
```

该结构突出时间、文本、身份不确定性、语义和来源关系，是跨阶段数据契约的核心信息。
