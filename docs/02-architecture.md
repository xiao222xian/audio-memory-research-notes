# 抽象架构与证据契约

## 分层的理由

音频处理层回答“有什么声音与文本”；身份层回答“哪些内容可以归给用户”；事件层回答“这些片段是否构成同一件事”；生成层回答“有足够证据写下什么”。各层面对的不确定性不同，强行把所有问题压进一个提示容易产生难以定位的错误。

公开讨论采用以下概念契约，字段名称为说明用途重新抽象，不对应私有接口：

| 概念 | 需要保留的内容 | 下游不能擅自做的事 |
|---|---|---|
| 输入证据 | 来源、时间范围、可用状态 | 将缺失输入标成可用 |
| 内容来源 | 现场、外放、混合或无法判断 | 将“检测到媒体”直接等同于整段无价值 |
| 身份线索 | 说话人候选、匹配依据、不确定性 | 将匿名说话人或低置信候选确定为用户 |
| 事件组织 | 输入片段集合、边界和排除原因 | 合并之后丢失来源关系 |
| 生成决定 | 生成、跳过、待补证据的原因 | 被要求必须填出一个故事 |
| 叙事陈述 | 可核对的证据与归因 | 仅凭引用格式合法就视为事实成立 |

## 检测、决策与切分

“含媒体”是观测标签；“整段过滤”是产品策略。一个混合片段可能包含背景节目与用户自己的讨论。如果直接删除全部，容易丢掉有价值内容；如果全部保留，下游又可能抓住其中最鲜明的媒体情节。

因此评测最好分别记录内容来源、期望动作和时间边界。保留、拦截、切分、待复核是这里提出的评估动作集合，不意味着历史实现已经完成了所有分支。

## 身份不确定性必须跨层保留

声纹或相似度给出线索，下游叙事却可能把所有对话统一写成第二人称。这会把上游的不确定性变成确定陈述。改进方向包括明确区分确认身份与候选身份、处理多人竞争、对第二人称陈述增加证据要求，并单独评估最终归因错误。

更强的声纹模型可能有帮助，但如果信息在接口或提示中被丢失，替换模型无法单独修复问题。

## 长期记忆的证据约束

可以将原始观察、可引用事实、事件摘要、跨事件模式和未来推断视为不同抽象层。长期归纳应保留来源，不应覆盖或抹除较低层证据；推断应与用户明确表达的事实区分。

这里给出的是通用设计反思。归档里存在记忆实验与设计材料，但未据此确认完整生产应用、长期收益或各层都得到独立验证。
