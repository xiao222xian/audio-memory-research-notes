# 产品定位与使用场景

## 将生活中的声音组织成可回看的内容

Spiro 的产品方向是把日常声音变成可持续使用的个人信息资产：从对话中提取事件，保留时间和参与者线索，再用用户容易阅读的形式呈现。项目关注的不只是转写完整度，也包括事件是否值得保留、内容是否属于用户，以及表达能否被原始资料支持。

整体体验可以概括为三个动作：记录日常、理解经历、重新连接。记录解决信息容易流失的问题；理解将分散片段组织为事件；重新连接则通过内容任务和记忆研究，探索过去经历与当前问题之间的关系。

## 一次完整的用户旅程

| 阶段 | 用户侧体验 | 系统侧工作 |
|---|---|---|
| 开始记录 | 通过录音入口提交声音资料 | 接收文件与时间信息，创建处理任务 |
| 建立身份线索 | 按流程提供注册语音 | 检查有效语音、声纹特征和录音质量 |
| 后台整理 | 无需逐段手工编辑转录 | 语音处理、转录、说话人区分与片段分析 |
| 形成事件 | 浏览连贯的生活片段 | 根据连续性和上下文组织完整事件 |
| 生成内容 | 阅读事件卡或其他内容任务结果 | 选择材料、生成结构化内容、保留引用 |
| 深入回看 | 查看来源、比较相关经历 | 事件追踪；记忆关联与语音交互由实验模块探索 |

该旅程说明项目各部分如何连接；不代表所有入口与内容形式均已面向商业用户开放。

## 内容产品的不同职责

**事件卡**围绕具体经历组织内容，强调时间、场景和事件依据。多事件卡还需要选择值得共同表达的材料，并允许在证据不足时跳过。

**洞察信件**面向一段时间的事件上下文，组织更长篇的表达。Agent 服务提供相应任务配置与语言校验，具体内容效果仍需人工评审。

**画像与洞察任务**整理事件中的相关线索，为其他内容提供上下文。项目展示的是观察与表达能力，不提供临床诊断或心理治疗效果声明。

**实时记忆对话**通过独立 Demo 展示按问题召回资料并用语音回答的可能性，同时以认知面板呈现相关信息。

## 典型使用场景

- **日常交流回看**：从多人对话中识别讨论的事情，整理为可读事件，避免把旁人的经历写成用户经历。
- **工作与计划回顾**：从交流内容中整理计划、决定及相关背景；是否形成待办需要具体产品规则支持。
- **阶段性生活观察**：将一段时间的事件组织给内容任务，帮助用户回看反复关注的话题。
- **带来源的记忆问答**：在 Demo 中对具体事实、时间和模式采用不同查询路径，避免所有问题都被泛化成抽象洞察。

## 产品价值如何落到工程

降低记录负担依赖可靠的采集和异步处理；内容有意义依赖事件理解与筛选；个性化依赖身份和上下文；长期可信依赖证据关联、更新机制与质量评测。项目由算法、业务服务、交互界面和研发工具共同支撑这些目标。
